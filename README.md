# 连词成句（lian.diuci.com）

每天一段必背课文。盘面上每个字都来自这篇课文：点住一个字，拖过相邻的字（横竖斜都算，
一条路不重复经过同一个格），连出原文里的句子；句子全找齐之后，按原文顺序排好。

篇目来自课标与统编教材的必背范围：小学 109 篇、初中 68 篇、高中 71 篇，共 248 篇能玩（内容仓 252 篇，跳过 4 篇，理由写在快照里）。
超过一盘的篇目按句子边界切成几段，一段一盘。

## 数据从哪来

内容仓 `diuci/k12-chinese-poetry` 是唯一的真源。本站构建期快照一份：

```bash
CONTENT_ROOT=../k12-chinese-poetry node tools/sync-corpus.mjs   # 生成 src/data/corpus.json
node tools/sync-corpus.mjs --check                              # 漂移就失败
node tools/build-readings.mjs                                   # 离线读音，运行时不查字典
```

快照里带着 `contentVersion`、来源文件的 sha256、每篇的 `authorDied` / `authorEraEnd` ——
公开哪篇课文，就同时公开凭什么说这篇可以公开。

## 玩的是哪一份正文

内容仓给每篇标了教材的背诵要求 `recite`：`full`（背全文）、`section`（背段落）、`line`（背名句）。
本站跟着它选正文，不自作主张：

- `recite=full` 且有全文 → 玩全文（`fullLinesPunct`）；
- 其余 → 玩必背单元（`linesPunct`）。

之前一律玩 `linesPunct`：醉翁亭记、将进酒、蜀道难、《论语》十二章这些写着「背全文」的篇目，
在站上只连得出几十个字的名句 —— 那是把「背全文」悄悄缩成「背两句」。现在每篇都带 `textSource`
（full / mingju），读者问「这段是不是课文」时有据可查。

## 每日题的历史冻结

选篇是「日期 → 词库里的第几篇」。词库一变（内容仓补了篇目、改了顺序、改了正文），
同一天的题就跟着变：玩家上周玩过的那一题，这周回放变成另一篇 —— 那不叫回放，那叫换题。

所以 `corpus.json` 里带一份 `history`：已经发出去的日子逐日记下是哪一篇哪一段。
冻的是「哪天玩哪一篇哪一段」，不是把当时的正文一起冻住：内容仓勘误之后回放改用改过的那份，
并在 `history.retexted` 留痕；词库里已经消失的篇目标成 `ghost`。明知是错的还照原样端给来背课文的人，这一条不能要。
`npm run sync:corpus` 在写新词库**之前**先用旧词库把日子冻下来；`check:puzzle` 逐条回放核过：
日子必须连续、每条必须还能解出正文、昨天必须已经冻上。冻结按本地日子写（玩家在哪个日子玩就是哪天），
CI 那台机器按 UTC 算今天 —— 差一天是允许的，晚两天以上报错。

## 玩法规则写在代码里

- `src/logic/layout.mjs`：拆句、切段、盘面生成、盘面校验。客户端与 tools/ 共用这一份。
- `src/logic/daily.mjs`：每日选篇与种子。同一天所有人同一题。
- `src/logic/game.ts`：找句 / 排句两阶段的规则。组件只负责画。

盘面约束：列数按 `[6,7,5,8,4]` 试，行数 ≤ 12，格子总数 ≤ 96，空洞不足一整行；
每句占一条不自交的八向路径，同一格不被两句共用。摆法用随机哈密顿路径，
找不到就退回蛇形路径 —— 蛇形对任何矩形都存在，所以任何长短组合都保证铺得满。

## 分站与内容仓的契约

内容仓 `diuci/k12-chinese-poetry` 是唯一的真源。分站读的是**快照**，不是内容仓本身：

1. **单向**：内容仓 → 本站快照。本站永不读另一个分站的文件。
2. **按需取**：本站要什么字段就取什么字段，不要的不进快照。这里要切好的 `units`
   和 `authorDied` / `authorEraEnd`（页面上要公开「凭什么这篇能公开」）；
   注释、译文、赏析这些本站用不到的东西一概不进来。
3. **快照随本站提交**，头部带 `contentVersion`、来源文件 `sha256`、跳过了哪几篇、为什么。
4. **CI 不 clone 内容仓**：本站只校验快照自洽与玩法成立。内容仓怎么改都不会让本站无故变红。
5. 更新快照是显式动作：`npm run sync:corpus` → 看 diff → 提交。内容仓变了而本站没重跑，
   `sync:corpus --check` 会指出 sha256 漂移 —— 但这条只在本地跑，不进 CI，理由同上。

代价说清楚：快照会滞后于内容仓。换来的是分站之间零依赖。
## 检查

| 命令 | 查什么 |
|---|---|
| `npm run verify` | 本地一条龙：下面这些按顺序全跑一遍，任何一步红就停 |
| `npm run selftest` | 八个工具各自的坏样本 |
| `npm test` | 玩法、盘面生成、繁体那一层的 35 条断言 |
| `npm run check:puzzle` | 276 个盘面全量生成 + 校验，最近 30 天的每日题可复现，冻结的历史逐条回放 |
| `npm run build:readings -- --check` | 读音快照重算一遍逐字节一致（顺带就是覆盖率） |
| `npm run check:corpus` | 快照与内容仓是否一致：sha256 漂移、篇目漂移、历史有没有洞 |
| `npm run check:legal` | LICENSE、公有领域逐篇核验、绝对化表述、联系入口 |
| `npm run check:build` | dist 齐不齐 + 23 个色值有没有被顺手改掉 |
| `npm run build:traditional -- --check` | 繁体产物重算一遍逐字节一致（词库或内容仓变了而本站没重算，当场露出来） |
| `npm run check:trad` | 繁体这一侧：覆盖、等长、与内容仓一致、界面词典两边齐、组件用到的词条都在 |
| `npm run smoke` | 真开浏览器把当天这一题连到完成态，简体繁体各一遍，繁体那一轮逐格比对画出来的字 |

只有八个工具：取数据三个（`sync:corpus`、`build:readings`、`build:traditional`），检查五个（`check-puzzle`、`check-legal`、`check-build`、`check-trad`、`smoke-lian`）。
`check:corpus` 是取数据那个工具自带的比对开关，
它以前只写在 README 里、没接进任何一条链 —— 一个存在但没人跑的检查，等同于没有检查。
读音的多音字统计是 `npm run report:readings`，给人看的，CI 不跑。

每个检查都带 `--selftest`：先证明它抓得住坏样本，再看它说「通过」值不值得信。

## 繁体这一侧

界面文案在 `src/locales/zh-cn.json` / `zh-tw.json`，开关在 `src/logic/locale.ts`（localStorage 键 `lian-locale`；
浏览器语言是 zh-TW / zh-HK / zh-MO 就默认繁体，顶栏那枚「繁/简」钮随时切）。

**课文的字形不在这里。** 本站不做第二次繁简转换：繁体全部取自内容仓已经派生好的那一份
（`k12-chinese-poetry/data/traditional.json`），那一遍是逐字核过来源页的 —— 来源页写作什么就是什么，
词组表只兜底。为什么这么定：本站自己转一遍等于凭空多出一套答案，而且同一篇会出现两种繁体形。
这件事真发生过一次：谏逐客书同一句在全文里被表换成「由餘」、在必背名句里照来源页作「由余」。

- `tools/build-traditional.mjs` 只做搬运与对齐核验：简体行与繁体行必须行数相等、逐行**码位数**相等；
  句子按 `splitUnits` **整组**切（与词库同一切法 —— 单字块并进前一句时会跨到下一行，逐行切就对不上）。
  内容仓覆盖不到的句子直接停，不许本站现编一个繁体形。
- 产物 `src/data/traditional.json` 只装「和简体不一样的那些」：`units`（1748 句）、
  `same`（繁简本来就同形的登记 —— 没有这份登记，运行时分不清「同形」与「漏了」，就会静默端出简体）、
  `titles` / `stages` / `volumes`（篇名、作者、朝代、学段、册次）。
- **玩法与判定全在简体那一遍上**：盘面按句子序号与位置匹配，繁体只是渲染层按码位换字形。
  增补平面字（三峡「绝𪩘」、劝学「𫐐」、谏逐客书「𫘝𫘨」）在 UTF-16 里占两个码元，
  一切取字与长度都按码位走，否则盘面与原文对不上。
- 干扰块记下自己是「哪一句第几字」抓来的（`Cell.from`）：只留一个字符就认不出它该长成哪个繁体字。
- 历史冻结跟着勘误走：`history.days` 冻的是「哪天玩哪一篇哪一段」，正文用改过的那份。
  中庸那句「愚夫愚妇亦能知与知之」是 2026-10-08 被内容仓删掉的拼出来的名句，回放不再端它，
  `history.retexted` 留了痕。明知是错的还照原样端给来背课文的人，这一条不能要。
- 闸门 `tools/check-trad.mjs`（17 项坏样本）：产物新鲜度、每句都有繁体形且码位等长、
  繁体形必须与内容仓一致、不许有多余映射、不许把同形写进产物、繁体侧不许留下只有简体才用的字
  （用的是内容仓那张 `STCharacters` 表和它登记过的「有意留下的字」，本站不自带一份字表）、
  界面词典两边键一致、参数占位符一致、组件里用到的每个词条都真的存在。

这条闸门分两半，CI 里跑的只是其中一半：CI 不 clone 内容仓，所以「与内容仓逐句比字」和
「繁体里不许留简体专用字」这两条在 CI 跑不了 —— 工具会当场把这一句打印出来，不许默默跳过。
本地跑 `npm run check:trad`（内容仓就在隔壁目录）才是全的；要它没有内容仓时直接失败，加 `--require-content`。
